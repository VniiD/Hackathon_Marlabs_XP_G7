Hackathon XP · G7 — Jornada do Assessor

Plataforma de inteligência para assessoria financeira

Um monólito modular em Python que consolida carteiras via Open Finance, cruza notícias e oscilações de mercado com o perfil de risco de cada cliente, e entrega ao assessor uma fila diária ordenada por criticidade — com um copiloto de voz via Gemini preenchendo o sistema pelo próprio cliente.

ArquiteturaMonólito modular
LinguagemPython
Tempo realRedis + WebSockets
IntegraçõesOpen Finance · Gemini API
PerfisAssessor / Cliente
01

Visão geral

O assessor acompanha dezenas de clientes manualmente — consultando fontes diferentes, cruzando notícias com carteiras e lembrando sozinho de eventos de relacionamento. A plataforma substitui essa rotina por um dashboard único: o cliente alimenta o sistema por voz ou pela própria carteira, e o assessor recebe uma lista do dia já ordenada por quem precisa de atenção agora.

Requisitos funcionais

Consolidado a partir do levantamento inicial (jornada do assessor) e da especificação técnica subsequente.

RF01
Gestão de perfis e autenticação — o sistema diferencia acessos entre Assessor e Cliente via autenticação segura (JWT).

Consolidação multicanal via Open Finance — integra automaticamente o patrimônio do cliente em outras instituições, unificando padrões díspares de dados.

RF04
Dashboard do cliente — exibe carteira atual, perfil de investidor, rentabilidade e acesso à agenda do assessor.
RF05
Agendamento inteligente — o cliente marca reuniões com base nos horários livres reais do consultor.
RF06
Solicitação de alteração de carteira — pedidos de rediversificação, aporte ou resgate disparam alerta imediato no painel do assessor.
RF07
Integração de mercado — consumo de APIs externas de cotação de moedas e notícias financeiras (ex.: CNN) em tempo real.
RF08
Motor de insights automatizados — processa grandes volumes de dados para gerar indicadores como FGC, over CP, ágio, deságio e break-even.
RF09
CRM de relacionamento — armazena histórico de interações, datas comemorativas e eventos de interesse de cada investidor.
RF10
Contexto pessoal do cliente — cadastro com hobbies, time de coração e preferências, usado para personalizar o contato do assessor.
RF11
Chat por voz (Gemini) — o cliente fala naturalmente e o sistema extrai intenções estruturadas (compra de ativo, agendamento) via function calling.
RF12
Fila de criticidade — o dashboard do assessor ordena clientes do mais ao menos crítico, combinando mercado, risco e relacionamento.

04

Arquitetura geral

Três camadas: interface adaptada por perfil, um monólito modular em Python, e uma camada de dados com persistência transacional e cache em tempo real.

FRONTEND — Assessor / Cliente
Aplicação web com interface adaptada por perfil via RBAC. Dashboards dinâmicos, gráficos de alocação, widgets de mercado (cotações, notícias) e módulo de agendamento.
↕ REST / WebSocket
BACKEND — Monólito modular Python
Regras de negócio, autenticação JWT, integração com Open Finance e APIs de mercado, motor de criticidade e webhooks para notificação em tempo real do assessor.
↕ Conexões / Pub-Sub
DADOS — Persistência e tempo real
Banco relacional para usuários, carteiras, ordens e agendas. Redis como cache e mensageria para propagação instantânea de ticks de mercado.

O backend é um monólito modular — não microsserviços — desenhado em bounded contexts para poder evoluir para serviços independentes caso o volume de clientes exija.

Módulos do monólito

Sete contextos delimitados (bounded contexts), cada um com responsabilidade única.

accounts
Autenticação e contexto pessoal

Perfis de Assessor e Cliente, senhas, tokens JWT, perfil de risco e mapa comportamental (hobbies, time, datas comemorativas).

portfolio
Gestão de carteiras

Ativos, posições, alocação e motor de rastreio de alterações solicitadas pelo cliente.

openfinance
Integração Open Finance

Consentimento, sincronização de saldos e ativos em instituições externas, consolidação do patrimônio geral do cliente.

market_intelligence
Mercado e notícias

Cotações em tempo real via cache Redis, coleta de notícias (RSS/API) e análise de sentimento cruzada com os ativos do cliente.

scheduling
Agenda e reuniões

Sincronização dos horários livres do assessor com a disponibilidade exibida ao cliente.

copilot_chat
Chat e voz via Gemini

Transcreve áudio, extrai intenção com function calling e executa ações nos outros módulos sem formulário manual.

advisor_dashboard · core
Motor de criticidade

Cruza mercado, risco e relacionamento para gerar a fila diária priorizada e a próxima melhor ação para cada cliente.

06

Motor de criticidade

A régua que decide quem aparece no topo do dashboard do assessor todos os dias. Combina o tamanho do impacto de mercado, a tolerância a risco do cliente e gatilhos de relacionamento.

Score = (Impacto de Mercado × Fator de Risco) + Gatilhos de Relacionamento
Impacto de mercado cruza a variação percentual de cada ativo (preço + sentimento de notícias) com o peso daquele ativo na carteira do cliente. Gatilhos de relacionamento somam pontos fixos por solicitação pendente no chat, aniversário do dia ou evento cadastrado.
× 1.8
Conservador
Alta sensibilidade a oscilações de renda fixa, câmbio e notícias negativas.
× 1.2
Moderado
Peso intermediário entre proteção e tolerância a volatilidade.
× 0.8
Arrojado
Tolera maior volatilidade sem necessidade de intervenção imediata.

Acima de 5–10 pontos (conforme o perfil), o sistema sugere "ligar urgentemente"; abaixo disso, entra na rotina normal de acompanhamento.

Código de referência

Implementação de referência do motor de criticidade diária (advisor_dashboard/engine.py).

advisor_dashboard/engine.pypython
from dataclasses import dataclass
from typing import List, Dict, Any
from enum import Enum

class RiskProfile(Enum):
    CONSERVADOR = 1.8
    MODERADO = 1.2
    ARROJADO = 0.8

@dataclass
class Client:
    id: str
    name: str
    risk_profile: RiskProfile
    portfolio_exposure: Dict[str, float]   # ex: {"PETR4": 0.40, "USD": 0.10}
    personal_info: Dict[str, Any]            # ex: {"soccer_team": "Palmeiras"}
    pending_chat_requests: int

class DailyAdvisorEngine:
    def __init__(self, market_sentiment: Dict[str, float]):
        # market_sentiment: impacto/sentimento de notícias por ativo.
        # valores negativos indicam risco/alerta.
        self.market_sentiment = market_sentiment

    def calculate_criticality(self, client: Client) -> float:
        market_impact = 0.0
        for asset, weight in client.portfolio_exposure.items():
            if asset in self.market_sentiment:
                sentiment = self.market_sentiment[asset]
                market_impact += abs(sentiment) * weight

        base_score = market_impact * client.risk_profile.value * 100
        base_score += (client.pending_chat_requests * 15.0)
        return round(base_score, 2)

    def generate_daily_dashboard(self, clients: List[Client]) -> List[Dict[str, Any]]:
        dashboard_items = []
        for client in clients:
            score = self.calculate_criticality(client)

            suggestion = "Rotina normal de acompanhamento."
            if score > 10.0 and client.risk_profile == RiskProfile.CONSERVADOR:
                suggestion = f"Ligar urgentemente: impacto de mercado em carteira Conservadora."
            elif client.pending_chat_requests > 0:
                suggestion = "Responder solicitação via chat/voz enviada pelo cliente."
            elif "aniversario" in client.personal_info.get("events_today", []):
                team = client.personal_info.get("soccer_team", "")
                suggestion = f"Mandar mensagem de aniversário (mencionar {team})."

            dashboard_items.append({
                "client_id": client.id,
                "client_name": client.name,
                "risk_profile": client.risk_profile.name,
                "criticality_score": score,
                "suggested_action": suggestion,
                "personal_context": client.personal_info
            })

        return sorted(dashboard_items, key=lambda x: x["criticality_score"], reverse=True)

O mesmo padrão de engine.py se repete em prioritization/ (versão inicial, baseada apenas em variação de mercado) — mantido aqui como registro da evolução do motor até incorporar risco e relacionamento.
